# SSH Fleet

Инструмент для массового выполнения команд на сетевых устройствах (коммутаторах, роутерах и т.п.) по SSH с агрегацией результатов. Есть два способа использования: консольная утилита (`cmd/`) и десктоп-приложение (`desktop/`) с графическим интерфейсом.

## Возможности

- Параллельное подключение и выполнение команд на списке устройств (настраиваемое число воркеров, повторные попытки подключения).
- Два режима выполнения команд:
  - **exec** — каждая команда выполняется в отдельной SSH-сессии (быстро, подходит для простых `show`-команд).
  - **интерактивный (PTY)** — одна SSH-сессия (псевдотерминал) на устройство, команды "печатаются" в неё по очереди. Нужен устройствам, которые по exec-каналу пускают только в режим просмотра и не позволяют войти в `configure terminal` (например Eltex) — конфигурационные команды (смена пароля, VLAN и т.п.) работают только в этом режиме.
- Результат по каждому устройству — отдельно.
- В десктоп-версии: сохранённые группы устройств, живой статус выполнения по каждому устройству, история всех запусков с полным выводом.

## Структура проекта

```
cmd/          - консольная утилита (config.yaml -> inventory -> commands -> output)
desktop/      - десктоп-приложение (Wails 2: Go-бэкенд + HTML/CSS/JS-фронтенд)
internal/     - общий код (SSH-клиент, executor, конфиги, история запусков и т.д.)
configs/      - пример config.yaml для консольной утилиты
inventory/    - пример списка устройств для консольной утилиты
commands/     - пример списка команд для консольной утилиты
```

## Консольная утилита

### Настройка

Все параметры — в `configs/config.yaml`:

```yaml
ssh:
  user: admin
  timeout: 10s
  known_hosts: ~/.ssh/known_hosts
  strict_host_key_checking: true
  pty: true              # интерактивный режим (нужен для Eltex и подобных)
  idle_timeout: 2s        # пауза тишины, после которой команда в PTY-режиме считается завершённой
  auth:
    type: key              # key | password
    private_key: ~/.ssh/eltex

executor:
  workers: 20
  retry:
    attempts: 3
    delay: 2s

inventory:
  file: ../inventory/hosts.yaml

commands:
  file: ../commands/commands.yaml

output:
  format: text            # на данный момент реализован только text
  file: ../output/result.txt
```

Список устройств — `inventory/hosts.yaml`, список команд — `commands/commands.yaml` (одна команда на строку). В PTY-режиме команды выполняются в общем контексте сессии — можно писать последовательности вида:

```yaml
commands:
  - configure terminal
  - username admin password NewPassHere
  - exit
  - write
```

### Запуск

```bash
cd cmd
go run .
```

Результат выполнения всех команд на всех устройствах пишется в один файл (`output.file` из конфига).

> На данный момент реализован только текстовый формат вывода (`format: text`); `json`/`csv` в конфиге пока не поддерживаются исполнителем.

## Десктоп-приложение

Тот же движок, но с графическим интерфейсом: список устройств с именами/адресами и сохраняемыми группами, вкладка команд с кнопкой запуска, живой статус выполнения по каждому устройству и история всех прошлых запусков с полным выводом.

### Сборка (Linux)

Нужны GTK3 и WebKit2GTK — как рантайм-библиотеки (обычно уже стоят в системе), так и dev-пакеты для сборки:

```bash
sudo apt install libgtk-3-dev libwebkit2gtk-4.1-dev
```

Сборка (собирать нужно обязательно с тегами `production` и `webkit2_41` — без них Wails на Linux соберёт нерабочую заглушку; `webkit2_41` — потому что современные дистрибутивы поставляют webkit2gtk 4.1, а не 4.0):

```bash
go build -tags "production,webkit2_41" -o sshfleet ./desktop
./sshfleet
```

Node.js/npm не нужны — фронтенд написан на чистом HTML/CSS/JS без сборки и встраивается в бинарник как есть.

### Данные приложения

Приложение хранит свои данные в `~/SSHFleet/`:

- `connection.json` — настройки SSH-подключения, заданные через вкладку «Настройки» (логин, аутентификация, PTY, таймауты, параллелизм). Пароль/пароль-фраза хранятся в открытом виде (права на файл — только для владельца) — по возможности используйте аутентификацию по ключу.
- `groups.json` — сохранённые группы устройств.
- `history/<время>_<описание>/` — результаты каждого запуска: `run.json` со статусами устройств и по одному `.txt`-файлу вывода на каждое устройство.

## Требования

- Go 1.26+
- Для десктоп-версии на Linux: `libgtk-3-dev`, `libwebkit2gtk-4.1-dev` (или `4.0-dev` со сборкой без тега `webkit2_41`, в зависимости от дистрибутива)
