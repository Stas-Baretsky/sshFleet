# SSH Fleet

Инструмент для массового выполнения команд на сетевых устройствах (коммутаторах, роутерах и т.п.) по SSH с агрегацией результатов по каждому устройству.

Два способа использования на общем движке:

- **десктоп-приложение** (`desktop/`) — графический интерфейс: список устройств, вкладка команд, живой статус выполнения, история всех прошлых запусков;
- **консольная утилита** (`cmd/`) — один прогон по YAML-конфигу, для скриптов и автоматизации.

## Возможности

- Параллельное подключение и выполнение команд на списке устройств (настраиваемое число воркеров, повторные попытки подключения).
- Два режима выполнения команд:
  - **exec** — каждая команда выполняется в отдельной SSH-сессии (быстро, подходит для простых `show`-команд);
  - **интерактивный (PTY)** — одна SSH-сессия (псевдотерминал) на устройство, команды «печатаются» в неё по очереди. Нужен устройствам, которые по exec-каналу пускают только в режим просмотра и не позволяют войти в `configure terminal` (например Eltex) — конфигурационные команды (смена пароля, VLAN и т.п.) работают только в этом режиме.
- Результат выполнения — отдельно по каждому устройству.
- В десктоп-версии: сохранённые группы устройств, живой статус по каждому устройству прямо во время выполнения, история всех запусков с полным выводом.

## Структура проекта

```
cmd/          - консольная утилита (config.yaml -> inventory -> commands -> output)
desktop/      - десктоп-приложение (Wails 2: Go-бэкенд + HTML/CSS/JS-фронтенд)
  install.sh          - сборка и установка для текущего пользователя (нужен интернет)
  package-linux.sh    - сборка офлайн-дистрибутива для Linux
  package-windows.sh  - сборка офлайн-дистрибутива для Windows
  packaging/          - то, что попадает внутрь офлайн-дистрибутивов
internal/     - общий код (SSH-клиент, executor, конфиги, история запусков и т.д.)
configs/      - пример config.yaml для консольной утилиты
inventory/    - пример списка устройств для консольной утилиты
commands/     - пример списка команд для консольной утилиты
```

## Требования

- Go 1.26+
- Для десктоп-версии на Linux — `libgtk-3-dev`, `libwebkit2gtk-4.1-dev` (или `4.0-dev`, в зависимости от дистрибутива — см. ниже). Node.js/npm не нужны: фронтенд на чистом HTML/CSS/JS, без сборки.
- Для десктоп-версии на Windows — ничего дополнительного для сборки (кросс-компиляция с Linux, без cgo/mingw); для запуска на целевой машине нужен Microsoft Edge WebView2 Runtime (обычно уже есть в Windows 10/11).

## Консольная утилита

Все параметры — в `configs/config.yaml`:

```yaml
ssh:
  user: admin
  timeout: 10s
  known_hosts: ~/.ssh/known_hosts
  strict_host_key_checking: true
  pty: true              # интерактивный режим (нужен для Eltex и подобных)
  idle_timeout: 2s        # пауза тишины, после которой команда в PTY-режиме считается завершённой
  auth:
    type: key              # key | password
    private_key: ~/.ssh/eltex

executor:
  workers: 20
  retry:
    attempts: 3
    delay: 2s

inventory:
  file: ../inventory/hosts.yaml

commands:
  file: ../commands/commands.yaml

output:
  format: text            # на данный момент реализован только text
  file: ../output/result.txt
```

Список устройств — `inventory/hosts.yaml`, список команд — `commands/commands.yaml` (одна команда на строку). В PTY-режиме команды выполняются в общем контексте сессии, поэтому можно писать последовательности вида:

```yaml
commands:
  - configure terminal
  - username admin password NewPassHere
  - exit
  - write
```

Запуск:

```bash
cd cmd
go run .
```

Результат выполнения всех команд на всех устройствах пишется в один файл (`output.file` из конфига).

> На данный момент реализован только текстовый формат вывода (`format: text`); `json`/`csv` в конфиге пока не поддерживаются исполнителем.

## Десктоп-приложение

Тот же движок, но с графическим интерфейсом: список устройств с именами/адресами и сохраняемыми группами, вкладка команд с кнопкой запуска, живой статус выполнения по каждому устройству и история всех прошлых запусков с полным выводом. Настройки SSH-подключения (логин, аутентификация, PTY, таймауты, параллелизм) задаются формой на вкладке «Настройки», а не файлом.

### Сборка и установка для себя (нужен интернет)

На Linux сначала нужны dev-пакеты GTK3/WebKit2GTK:

```bash
sudo apt install libgtk-3-dev libwebkit2gtk-4.1-dev
```

Дальше — сборка и установка одной командой:

```bash
./desktop/install.sh
```

Соберёт приложение (с тегами `production,webkit2_41` — без них Wails на Linux соберёт нерабочую заглушку; `webkit2_41`, потому что современные дистрибутивы поставляют webkit2gtk 4.1, а не 4.0) и установит его для текущего пользователя, без sudo: бинарник в `~/.local/share/sshfleet/`, иконку и ярлык в меню приложений (`~/.local/share/applications/sshfleet.desktop`). Дальше запускается как любое обычное приложение — через меню или `~/.local/share/sshfleet/sshfleet`. Повторный запуск скрипта после изменений в коде пересобирает и переустанавливает поверх.

Собрать без установки: `go build -tags "production,webkit2_41" -o sshfleet ./desktop`.

### Раздача дистрибутива без интернета

Чтобы поставить приложение на машины без доступа в интернет, нужен **офлайн-дистрибутив**: помимо самого приложения он содержит все системные зависимости (GTK3/WebKit2GTK на Linux, WebView2 Runtime на Windows), которые иначе взялись бы из интернета. Собирается на машине с интернетом, переносится на целевую флешкой/по сети и там ставится полностью офлайн. Сами дистрибутивы в git не хранятся (десятки-сотни МБ) — собираются заново скриптами по мере необходимости.

#### Linux (Ubuntu/Debian, x86-64)

```bash
./desktop/package-linux.sh
```

Соберёт бинарник и скачает ~150 МБ `.deb`-пакетов (GTK3, WebKit2GTK и их полное дерево зависимостей — список см. в `desktop/packaging/linux/deps.txt`) в `dist/sshfleet-linux-amd64-offline.tar.gz`. На целевой машине:

```bash
tar xzf sshfleet-linux-amd64-offline.tar.gz
cd linux
./install.sh
```

Скрипт сам определит, чего не хватает, и поставит из приложенных `.deb` (нужен sudo, интернет — нет), после чего установит само приложение так же, как `desktop/install.sh`. Если недостающие библиотеки уже есть в системе — просто пропустит этот шаг.

#### Windows (x86-64)

```bash
./desktop/package-windows.sh
```

Кросс-компилирует `.exe` (интернет для этого не нужен — у Wails под Windows чистый Go-бэкенд без cgo/mingw) и один раз скачивает офлайн-инсталлятор Microsoft Edge WebView2 Runtime (~200 МБ, кешируется в `dist/.cache/`, дальше не перекачивается). Результат — `dist/sshfleet-windows-amd64-offline.zip`. На целевой машине: распаковать и запустить `windows\install.bat` — он поставит WebView2 (если его ещё нет — на многих Windows 10/11 он уже стоит по умолчанию) и создаст ярлыки на рабочем столе и в меню Пуск.


### Данные приложения

Приложение хранит свои данные в `~/SSHFleet/`:

- `connection.json` — настройки SSH-подключения из вкладки «Настройки». Пароль/пароль-фраза (если выбрана парольная аутентификация) хранятся в открытом виде, права на файл — только для владельца; по возможности используйте аутентификацию по ключу.
- `groups.json` — сохранённые группы устройств.
- `history/<время>_<описание>/` — результаты каждого запуска: `run.json` со статусами устройств и по одному `.txt`-файлу вывода на каждое устройство.
